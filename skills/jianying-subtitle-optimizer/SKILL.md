### 第 0 步：先探测画幅，再提问确认横/竖屏（2026-11-12 新增铁律）
执行修改前，必须先运行 `--probe` 只读探测最新草稿的 `canvas_config` 与主视频分辨率：

### 方式 A：CLI 极速管道（耗时 < 3 秒）

*(如需指定草稿：加 `--draft "草稿名称"`；未传 `--horizontal`/`--vertical` 时按 `canvas_config` 自动判断；如需跳过自动剪气口：加 `--no-trim-silence`)*
*(若草稿已被切碎需要按原文重排：加 `--restore-lines "原始台词.json"`，文件格式 `{"lines": ["第一句", "第二句", ...]}`；还原对不上会硬失败、不写盘)*

1. 自动定位最新草稿并释放剪映内存锁（强校验返回主页且 `.locked` 消失，防止剪映内存旧状态覆写磁盘）；

## 🚀 子代理并发提速架构（当台词较长或用户要求“快一点”时必用）

当字幕行数较多（> 30 句）或用户明确要求“**快一点**”、“**并发**”、“**调用子代理**”时，智能体必须采用**“分块并发分析 ➔ 单次原子写回”**的高性能架构：

### 1. 为什么不能让多个子代理同时写同一个草稿？
* 剪映草稿全部存储在唯一的 `draft_content.json` 中。若多个子代理同时直接修改文件，必然产生**文件写入竞争冲突（Race Condition）**，导致草稿损坏或数据丢失；
* 因此：**“分析与校对”充分并发，“工程写入”单次原子执行**。

### 2. 三步并发流水线（极速零冲突）
* **第一步：主代理切片分发（Parallel Dispatch）**：
  - 主代理按 20~30 句为一个批次切片，调用 `task` 并发派发 N 个子代理；
  - 每个子代理独立且同时完成：专有名词纠错、标点清除、长句 `\n` 对称折行、核心重点词高光标注。
* **第二步：内存秒级汇聚（In-Memory Merge）**：
  - 主代理等待所有子代理交付，毫秒级拼接为完整的标准台词与重点词列表。
* **第三步：极速原子写回（Atomic One-Shot Writeback）**：
  - 主代理一次性将汇聚好的参数喂给 `auto_subtitle_workflow.py` 或 MCP 工具；
  - 释放锁 ➔ 单次加密 ➔ 多副本覆盖 ➔ 重载打开，全程耗时仅 2~3 秒，零冲突、零等待！

### 第二步：智能校对与纠错铁律

智能体对字幕逐句进行专业校准，严格遵循四大规则：

1. **【铁律】严格 1 对 1 行数对齐（总行数绝对守恒）**：
   - 校对后的列表长度必须与原文本行数完全相等（`len(corrected_lines) == len(lines)`）；
   - **严禁擅自合并行或跨行拆分**，确保每一行对应剪映时间轴上的一个独立字幕切片！
2. **清除口语废话与结巴卡顿**：
   - 彻底剔除“这个呃”、“然后呢”、“啊”、“那额度了”、“嗯”、“诶”等口语碎词，保持呼吸感与节奏感。
3. **专有名词与技术模型专业校准（结合本机事实）**：
   - `Claude open 十五点五` / `OPPO S5.5` ➔ **Claude Opus 5.5**
   - `GPT6.1SO` ➔ **GPT-6.1-Sol**
   - `workbody的H3` ➔ **WorkBuddy 的 Hy3**
   - `GPT plus` / `Claude的Pro` ➔ **ChatGPT Plus** / **Claude Pro**
   - `萤石的leak2Pro` / `影石的link2pro` / `影持的立卡2` ➔ **影石 Link 2 Pro**（硬件型号误听，已固化为 `_TERM_FIXES` 正则）
   - 专业工具正字：`FocuSee`、`OpenFilm`、`FaceFusion`、`overlay-studio` 等。
   - 2026-11-12 新增 `_TERM_FIXES`：`openwrt / w r t → OpenWrt`、`Git Hub → GitHub`、`让a → 让AI`、`你的i → 你的AI`、`omp → OMP`、`mcp → MCP`。
   - **【铁律】** 新发现的误听变体必须同步写进 `auto_subtitle_workflow.py` 的 `_TERM_FIXES`，禁止只手工改当前草稿了事；替换后的英文词由 `_protected_spans` 保证不被拦腰切断。
4. **语法倒错纠偏**：
   - 修正“审美了很好” ➔ “审美非常好”、“我给他建议” ➔ “我给大家的建议”。

### 第三步：调整字幕样式与音量标准（克制、高保真、杜绝花里胡哨）

在写回剪映时，以**用户舒适阅读的「纯净基础字幕」为默认标准**，杜绝过度包装：

#### 1. 核心铁律：单行顺次滚动（严格 6~9 字，说完即切下一句）
- **字数区间卡死在 6~9 字（不低于 5~6 字，上限不超 10 字）**：
  * **【下限防碎词（≥ 5~6字）】**：严禁出现 `有人说`(3字)、`但我觉得`(4字)、`只是少数`(4字) 这类只有 3~4 字的单薄碎词一闪而过，必须与相邻短语合理聚合；
  * **【上限防截断（≤ 9~10字）】**：凡超过 10 字的句子，必须按语意气口切成独立的单行时间轴切片，严禁单条过长触发剪映自动换行导致“寡字掉行”或出界裁切！
- **纯单行顺次接替**：每个切片为独立时间轴文本，说一句出单句，说完立即消失并滚动切入下一句，胸前永远只保留一行，干净利落。

#### 1.1 【2026-10-29 新增铁律】按「显示宽度」排版，英文词绝不拦腰切断

> **事故复盘**：早期引擎按**字符数**判断行长，把 `chatgpt` 切成 `cha` / `tgpt`、`session` 切成 `se` / `ssion`、`open a` 单独成行。真机成片出现「断头英文」，属于不可交付的硬伤。

- **宽度计算铁律**：半角英文/数字按 `0.5` 宽、中文按 `1.0` 宽计算，行长上下限以**宽度**为准（上限 `10.0`、下限 `4.0`）。`ChatGPT`(宽 3.5) 与 7 个汉字等价，不得再按 7 个字符误判超长。
- **英文词不可分割铁律**：切点严禁落在 ASCII 单词内部（`[A-Za-z0-9'’._+-]*` 视为原子 token）。宁可让该行略宽，也绝不把专有名词劈成两半。
- **虚词避让铁律**：切点尽量不落在 `的/得/地/了/着/吗/呢/吧/啊` 之前，杜绝「…别忘了留下你 / 的点赞和关注」这类把虚词甩到下一行开头的断句。
- **专有名词正字铁律**：`chatgpt → ChatGPT`、`open a / openai → OpenAI` 自动校准；英文词必须整体落在同一切片内。
- **幂等铁律**：引擎必须可重复运行。对已被切碎的草稿，先用 `--restore-lines`（原始台词 JSON）还原成整句再重排，避免「越切越碎」；还原对不上时**必须硬失败中止写入**，绝不写入半成品。
- **并发编辑保护铁律**：写回前若发现草稿内容与已知原文不符（用户正在剪映里手改），**立即停手并向用户确认**，严禁覆盖用户的手动编辑。

#### 1.1.1 【2026-11-06 新增铁律】语气词、重点词底色、动效全片覆盖（用户实测反馈）

> **事故复盘**：用户看完成片反馈「还有『阿拉』『啊』『呢』」「重点词要加底色你没加」「重点词动画和音效好像都没有」。回读加密草稿审计后确认，四项其实全都没真正落地：
> - `strip_fillers()` 只删 `[呃嗯诶]`，**25/68 条**残留「啊/呢/啦」；
> - `extract_highlight_keyword()` 写死了一组**特定视频**的业务词（「所有项目 / dqtx.cc / 生活下限」…），换一支片子 **0 命中**，亮黄高亮 `0/68`；
> - `background_style = 0`、`check_flag = 47`，缺 `16` 位，底色**根本不会渲染**；
> - `cue_indices` 写死切片 `0/1/4/6/8/13/15/21/25`，全部挤在**前 39 秒**，后面 67 秒一片空白；音效 `vol=0.60` 又被 `+7.0 dB` 人声盖住 → 用户观感「好像没有」。

- **语气词清理铁律**：`strip_fillers()` 统一清 `[啊呢啦吧嘛哦噢额诶嗯呃]`，顺带修 `是了(?=[用把在])` 这类识别赘字；`网吧|吧台|吧唧|呢喃|呢子|啦啦队|干嘛|好嘛|啊哈|哦豁|嗯哼|阿拉丁` 等实词**先占位保护、后还原**，严禁一刀切误删。清理必须同时作用于 `_match_key()` 与切分入口，保证 `--restore-lines` 幂等仍可对上。
- **重点词通用识别铁律**：四级兜底 = `专有名词 → 英文/型号 ASCII token → 通用工具方法论词库 → 通用场景词库`，返回 `(词, 强度)`。**严禁写死单支视频的业务词**，否则换片必然 0 命中。句内高亮字号固定 `16.5`（旧代码误写 `15.5`）。
- **底色落地铁律**：底色是**文字素材级属性，不是 `styles[]` 局部**。强重点词所在行设 `background_style=1`、`background_color="#181818"`、`background_alpha=0.85`、`background_round_radius=0.20`、`background_width/height=0.14`（`pyJianYingDraft.TextBackground` 默认值），并把 `check_flag = 47 | 16 = 63`。缺 `16` 位剪映直接不渲染。
- **全片覆盖铁律**：动效/音效卡点由 `pick_cue_indices()` 按**时间分 7 桶 + 每桶挑强重点词**动态生成，覆盖开场到收尾；**严禁写死切片索引**。音效 `vol` 提到 `0.75~0.80`（仍远低于人声线性增益 `2.2387`），原 `0.55~0.65` 在 `+7 dB` 人声下实测听不见。
- **素材字段一次写全铁律**：音效素材写入时带 `duration`（`ffprobe` 探测真实微秒数）、`check_flag=1`、`wave_points=[]`、`type="none"`，segment 带 `visible=True`；**不要依赖「剪映打开后再补全」**。动画对象复用草稿中剪映已补全的模板（含本机 effect cache `path`），保证首次打开即渲染。

#### 1.2 【2026-10-29 新增铁律】轨道保全 + 明暗通吃的描边

> **事故复盘（一）**：引擎曾用 `data["tracks"] = [video_track, text_track]` 重建轨道列表，把用户手工加的**画中画整条删掉**（贴纸轨同样中招）。这是不可接受的数据损失。
> **事故复盘（二）**：录屏类素材「白底网页」与「深色网页」交替出现，白字在白底上几乎不可见；用户手动改成黄字的片段还会**丢失阴影**，更糊。

- **轨道保全铁律（最高优先级）**：写回时只允许替换**字幕轨的 segments** 与**同名留存音效轨**；画中画（第二条及以后的 video 轨）、贴纸、特效、BGM 等所有轨道必须原样保留，且保持原有层级顺序。动画素材 `material_animations` 只清理「已无人引用」的旧字幕动画，**严禁整体覆盖**。
- **描边铁律（明暗通吃）**：一律使用 **白字 + 黑描边 + 60% 阴影**，不按画面配色（同一支视频里明暗背景交替时，任何单一字色都会在某半边失效）：
  - `styles[].strokes = [{"content": {"solid": {"alpha": 0.9, "color": [0,0,0]}}, "width": 0.08}]`
  - 素材级同步：`border_width = 40.0`、`border_color = "#000000"`、`border_alpha = 0.9`
  - **`check_flag` 必须同时置位描边(8)与阴影(32)**：`7 | 8 | 32 = 47`，否则剪映不渲染描边
  - 重点词高亮段（16.5 亮黄加粗）**同样要带描边与阴影**，不得只改颜色

#### 2. 基础字幕黄金排版规范（Aa研宋体经典阴影 + 句内放大高亮）

#### 3. 场景化重点词动画与卡点音效规范（心法：懂语境、知克制）

在口播视频中，字幕动效的灵魂在于**“根据当时的语境与情绪，赋予最匹配的进场姿态”**，同时遵守**“严格克制，绝非每个重点词都加”**的铁律：

1. **克制率铁律（20%~30% 原则）**：
   - 全片绝不能句句加动画（全加等于没加，且会造成严重视觉疲劳）；
   - 仅对全片最核心的 **5~8 处关键情绪转折点** 赋予入场动效，其余重点词仅保留句内放大 16.5 + 亮黄高亮（静态呈现），形成**“动静交替、有张有弛”**的自然节奏。
   - **全片覆盖铁律（2026-11-06）**：这 5~8 处必须按时间分桶**均匀铺满全片**（开场 / 前段 / 中段 / 后段 / 收尾），且落在强重点词所在切片上。**严禁写死切片索引** —— 旧版 `0/1/4/6/8/13/15/21/25` 全挤在前 39 秒，后 67 秒毫无动静，用户直接反馈「动画音效好像都没有」。

2. **五大语境与推荐入场动画匹配心法**：

* **音效搭配铁律（2026-11-06 修订）**：音效仅与这 5~8 处动效毫秒级同步触发；音量 `0.75 ~ 0.80`。旧标准 `0.55 ~ 0.65` 在人声已增益 `+7.0 dB`(`volume=2.2387`) 的工程里会被完全盖住，用户实测「听不到」；`0.75~0.80` 仍显著低于人声线性增益，不会喧宾夺主。音效素材必须自带 `duration / check_flag=1 / wave_points=[] / type="none"`，segment 带 `visible=True`。
